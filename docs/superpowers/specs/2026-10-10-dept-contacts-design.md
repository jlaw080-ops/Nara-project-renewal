# 실행부서 담당자 연락처 설계

## 요약

- **주제**: 실행부서를 고칠 때 부서명과 함께 부서장·실무 담당자의 이름·직위·직통번호를 한 화면에서 입력한다. 공고문에서 실행부서를 찾을 때 실무 담당자 연락처도 함께 읽어 채운다.
- **배경**: 지금은 부서명과 부서장 연락처가 다른 폼이고, 실무 담당자 칸은 없다. 공고문 끝의 문의처에는 대개 담당 부서 전화가 적혀 있다(예: "용역에 관한 사항: 건축과 ☎ 051-605-6231"). 지금은 부서명만 읽고 번호는 버린다. 영업 전화를 걸려면 이 번호가 필요하다.
- **결론**: 연락처는 기관+부서 단위 표(`dept_contact`)에 실무 담당자 칸을 더해 둔다. 실행부서 "고치기" 폼 하나로 7칸을 저장한다. 실행부서를 찾는 규칙과 Claude 질문이 담당자 연락처도 함께 읽어 **빈 칸만** 채우고 "공고문" 표시를 남긴다. 이미 받아 둔 공고문으로 기존 사업을 한 번 채우는 명령을 둔다.

## 1. 정한 것

| 항목 | 결정 | 근거 |
|---|---|---|
| 실무 담당자 저장 단위 | 기관+부서 (부서장과 같은 표) | 사용자 선택(2026-10-10). 한 번 입력하면 같은 부서 사업에 모두 보인다 |
| 자동 채움 범위 | 찾은 것만 채우고, 사람이 입력한 값은 덮지 않는다. 자동으로 채운 칸에 "공고문" 표시 | 사용자 선택 |
| 기존 사업 | 받아 둔 첨부파일을 다시 읽어 한 번 채우는 명령 (`nara enrich contacts`) | 사용자 선택. 나라장터 재조회·Claude 호출 없음 |
| 입력 폼 | 실행부서 고치기 폼 하나로 부서명·부서장 3칸·실무 담당자 3칸 | 사용자 요청. 따로 있던 "부서장 연락처" 폼은 없앤다 |
| 사람이 저장하면 | 그 부서 연락처의 "공고문" 표시를 모두 지운다 | 사람이 폼을 보고 저장한 값은 사람이 확인한 값이다 |
| 계약부서 전화 | 넣지 않는다 | 재무과·회계과 번호는 영업 대상이 아니다 |
| 출력 양식 15칸 | 그대로. "전화번호" 칸은 부서장 직통 → 실무 담당자 직통 → 공고 기재 번호 순 | 칸을 늘리지 않는다 |

## 2. 저장 구조

`dept_contact`에 칸을 더한다(기존 DB는 `migrate`의 `_add_column`으로).

```sql
staff_name     TEXT,   -- 실무 담당자
staff_position TEXT,
staff_tel      TEXT,   -- 직통번호
auto_fields    TEXT    -- 공고문에서 자동으로 채운 칸 이름. 쉼표로 잇는다 (예: 'staff_tel,staff_name')
```

- `auto_fields`에 적힌 칸만 화면에 "공고문" 표시가 붙는다.
- 사람이 저장하면 `auto_fields = NULL`, `updated_by = 사용자`. 자동 채움은 `updated_by = NULL`.
- 6칸이 모두 비면 줄을 지운다(지금 규칙 유지).

## 3. 공고문에서 담당자 읽기

### 3.1 규칙 (`dept_rules.find_staff(text, dept)`)

실행부서 이름이 나오는 자리마다 그 뒤 120자 안을 본다. 다른 부서 이름이 먼저 나오면 거기서 끊는다 — "건축과 … 재무과 ☎051-605-4154"의 번호를 건축과 것으로 읽으면 안 된다.

| 찾는 것 | 규칙 | 예 |
|---|---|---|
| 직통번호 | `0으로 시작하는 2~3자리 - 3~4자리 - 4자리`. `☎`·괄호·점·공백 구분을 허용하고 `0xx-xxx-xxxx`로 정리. 1588·1577·1544·080으로 시작하면 뺀다(콜센터) | "건축과 ☎ 051-605-6231" → 051-605-6231 |
| 이름·직위 | `한글 2~4자 + 직위` (주무관·사무관·서기관·주사보·주사·주임·계장·팀장) | "건축과 김철수 주무관" → 김철수 / 주무관 |
| 이름만 | `담당(자): 한글 2~4자` | "담당자: 홍길동" → 홍길동 |

번호가 있는 자리를 먼저 쓰고, 없으면 이름이 있는 자리를 쓴다. 아무것도 없으면 `None`.

### 3.2 Claude (`llm.ask_dept`)

같은 질문에 두 줄을 더 받는다. 추가 호출은 없다.

```
담당자: <이름 직위 또는 없음>
전화: <실행부서 전화번호 또는 없음>
```

규칙 두 줄을 더한다: "담당자·전화도 공고문에 적힌 것만 적는다", "계약부서 전화는 적지 않는다".

받은 값은 `verify_staff(text, staff)`로 거른다 — 번호는 숫자만 남겨 원문에 있을 때, 이름은 원문에 글자 그대로 있을 때만 쓴다. 직위는 이름이 살아남았을 때만 쓴다. 실행부서 답이 확정되지 않으면(`verify_answer` 실패) 담당자도 쓰지 않는다.

### 3.3 채우기 (`dept.fill_contact`)

실행부서가 확정되는 두 경로(규칙·Claude) 끝에서 부른다.

1. 규칙 3.1로 먼저 찾는다. Claude 답이 있으면 빈 칸만 Claude 값으로 보탠다.
2. `dept_contact`(기관, 부서)에서 **비어 있는 칸만** 채우고, 채운 칸 이름을 `auto_fields`에 더한다. 줄이 없으면 만든다(`updated_by = NULL`).
3. 사람이 넣은 값(`auto_fields`에 없는 값)은 절대 덮지 않는다.
4. 채운 건수는 `DeptRun.contacts_filled`로 세어 명령 끝에 보여 준다.

## 4. 기존 사업 채우기 (`nara enrich contacts`)

- 대상: 숨기지 않은 사업 중 확정된 실행부서가 있고(사람·규칙·Claude·이관 모두), 그 기관+부서의 실무 담당자 3칸이 모두 비어 있는 것.
- 그 사업 공고의 **받아 둔** 첨부 텍스트(`attachment.status = 'ok'`)를 공고 최신순·첨부 순서대로 읽어 3.1 규칙으로 찾는다. 처음 찾은 문서에서 멈춘다. 내려받기·Claude 호출은 하지 않는다.
- 채우기는 3.3과 같다. 사업마다 커밋한다.
- `--dry-run`이면 무엇을 채울지(기관·부서·사업·칸·값)만 보여 주고 쓰지 않는다.
- 실행 순서: DB 백업 → `--dry-run`으로 미리보기 → 실행.

## 5. 화면

### 5.1 실행부서 고치기 폼

| 칸 | 이름 | 검사 |
|---|---|---|
| 실행부서 | `exec_dept` (+ 후보 고르기 `pick`, 근거 `snippet`) | 지금 규칙 |
| 부서장 | `head_name`, `head_position`, `head_tel` | 이름·직위 50자, 번호는 숫자와 `-`로 9~11자리 |
| 실무 담당자 | `staff_name`, `staff_position`, `staff_tel` | 같음 |

- 처음 열면 부서장·담당자 칸에 지금 값이 들어 있다. 공고문에서 채운 값은 칸 옆에 "공고문" 표시.
- 처음 열면 실행부서 칸과 근거 문장에 지금 값이 들어 있다. 후보를 고르려면 실행부서 칸을 비운다.
- 저장하면 실행부서 저장(`save_dept`) 뒤 같은 트랜잭션에서 연락처 저장(`save_contact`). 연락처는 지금 실행부서의 기관+부서에 붙는다.
- **부서명을 바꾸면 연락처는 저장하지 않는다.** 폼에 든 값은 옛 부서 것이라 새 부서 줄에 쓰면 그 부서 담당자를 덮는다. "부서가 바뀌어 연락처는 저장하지 않았습니다"를 띄우고, 새 부서의 연락처는 다시 고치기에서 적는다.
- 저장 안내: "실행부서", "연락처" 중 바뀐 것만.
- 기존 `/project/<id>/contact` 주소와 "부서장 연락처" 고치기 링크는 없앤다.

### 5.2 보기

"실행부서" 제목 아래 두 줄:

```
부서장      홍길동 · 과장 · 051-000-0000
실무 담당자 김철수 · 주무관 · 051-605-6231 (공고문)
— 부산광역시 부산진구 건축과 공통 · 2026-10-10 홍길동
```

실행부서가 없으면 두 줄 대신 "실행부서를 확정하면 연락처를 적을 수 있습니다".

### 5.3 안전

쓰기는 기존 `_guard_writes`·버전 비교(`version`)·`BUSY_MESSAGE` 처리를 그대로 탄다. 버전에는 연락처 값도 들어가서 연락처만 고친 경우도 동시 수정을 잡는다. 부서 저장과 연락처 저장은 하나의 트랜잭션이다(저장 함수가 열린 트랜잭션 안에서는 중간에 커밋하지 않는다).

## 6. 테스트

| 테스트 | 왜 중요한가 |
|---|---|
| 부서 뒤 번호를 읽고, 계약부서 번호와 콜센터 번호는 읽지 않는다 | 영업 전화가 재무과·조달청으로 가면 안 된다 |
| 이름·직위, "담당자: 이름" 꼴을 읽는다 | 담당자 이름이 있으면 바로 통화할 수 있다 |
| Claude 답의 담당자·전화는 원문에 있을 때만 쓴다 | 짐작한 번호를 저장하면 안 된다 |
| 규칙 확정·Claude 확정 모두 연락처를 채우고 `auto_fields`에 남긴다 | 두 경로가 같은 결과를 내야 한다 |
| 사람이 넣은 값은 자동 채움이 덮지 않는다 | 사람이 확인한 값이 우선 |
| 사람이 저장하면 "공고문" 표시가 사라진다 | 표시가 남아 있으면 사람이 검토했는지 알 수 없다 |
| 실행부서 폼 하나로 7칸이 저장되고 같은 부서 다른 사업에 보인다 | 요청의 핵심 |
| 부서명을 바꾸면 연락처는 저장하지 않고 새 부서의 기존 연락처가 그대로다 | 옛 부서 연락처가 새 부서 담당자를 덮으면 안 된다 |
| 계약부서·조달청·팩스 번호는 실행부서 번호로 읽지 않고, 문의처 신호어 뒤 자리를 우선한다 | 검토에서 잡힌 실제 공고문 꼴 |
| 부서 저장과 연락처 저장은 함께 되돌려진다 | 반만 저장되면 다음 저장이 충돌로 막힌다 |
| `enrich contacts --dry-run`은 쓰지 않고, 실행은 빈 칸만 채운다 | 실제 DB에 돌리기 전 확인 |
| 기존 `/contact` 주소는 404 | 폼이 둘이면 값이 엇갈린다 |

기존 테스트 815건은 그대로 통과해야 한다. 기존 연락처 테스트(`/contact` 경로)는 새 폼 기준으로 고친다.

## 7. 범위 밖

- 출력 양식 15칸에 실무 담당자 칸 추가.
- 부서 연락처 일괄 조회 화면.
- 공고문에 없는 번호를 다른 곳(홈페이지·전화번호부)에서 찾는 것.
