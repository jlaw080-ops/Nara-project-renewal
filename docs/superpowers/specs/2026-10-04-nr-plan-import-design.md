# 신재생에너지센터 설치계획서 가져오기 설계

## 요약

- **주제**: 크롬 확장 프로그램([energyAgency-reneaablePlan](https://github.com/jlaw080-ops/energyAgency-reneaablePlan))이 신재생에너지센터(nr.energy.or.kr)에서 읽은 설치계획서를 나라 앱이 직접 받아 사업에 붙인다.
- **배경**: 설치계획서에는 공식 신재생 계획(에너지원·형식·용량), 착공·준공예정일, 주소, 의무기관 담당부서가 있다. 지금 나라 앱은 이 값을 시트 이관이나 사람 입력으로만 얻는다. 신재생에너지센터는 휴대폰 인증으로 로그인하므로 나라 앱이 예약 작업으로 직접 읽을 수 없다.
- **결론**: 수집은 확장 프로그램이 맡고 나라 앱은 토큰으로 인증하는 받는 주소(`POST /api/nr-plans`)로 결과를 받는다. 받은 설치계획은 기관·건물명·주소로 사업과 짝을 짓는다. 짝이 없으면 새 사업으로 추가하고 애매하면 사람이 연결 화면에서 고른다. 반영할 때 사람이 웹에서 고친 값은 덮지 않는다.

## 1. 정한 것

| 항목 | 결정 | 근거 |
|---|---|---|
| 전달 방식 | 확장 프로그램 → 나라 앱 받는 주소 (A안) | 시트를 거치지 않아 손이 안 간다. 신청번호로 같은 건을 가린다 |
| 나라 앱에 없는 설치계획 | 새 사업으로 자동 추가 | 나라장터 공고로 잡히지 않은 공공건물도 영업 대상이다 |
| 기존 값과 충돌 | 사람이 웹에서 고친 값만 지키고, 나머지는 설치계획서 값으로 바꾼다 | 설치계획서는 기관이 공단에 낸 공식 자료다 |
| 6종에 없는 에너지원 | **(검토 필요 — 권장안)** 에너지원·형식 목록을 DB 표로 옮긴다. 새 종류는 단가 없이 자동 추가하고 단가 관리에서 단가를 넣는다 | 지금 목록은 코드에 고정된 6종이다. 태양열·수열 등이 들어오면 입력 화면에서 고를 수 없다 |

## 2. 전체 흐름

```
[신재생에너지센터]  ←로그인(휴대폰 인증)─  사람
        │ 확장 프로그램이 신청서 팝업을 하나씩 읽음
        ▼
[확장 프로그램] ──POST /api/nr-plans (Bearer 토큰)──▶ [나라 앱]
        │ (시트 기록은 설정에 따라 함께 유지)                │
        ▼                                                ▼
   [구글 시트]                                    nr_plan 표에 원문 저장
                                                          │ 짝 찾기
                                         ┌────────────────┼────────────────┐
                                    확실한 짝 1건       후보 없음        애매함
                                         │                │                │
                                      자동 연결       새 사업 추가     연결 화면(사람)
                                         └────────┬───────┘
                                                  ▼
                                   사업에 반영 (사람이 고친 값 제외)
```

## 3. 받는 주소

`POST /api/nr-plans`

- **인증**: `Authorization: Bearer <토큰>`. 토큰은 `.env`의 `NARA_IMPORT_TOKEN`에 둔다. 비교는 `hmac.compare_digest`로 한다. 토큰이 비어 있으면 받는 주소 자체를 끈다(404).
- **로그인·같은 출처 검사 예외**: 이 주소만 `PUBLIC_ENDPOINTS`에 넣고 쓰기 출처 검사(`_guard_writes`)에서도 뺀다. 대신 토큰이 없거나 틀리면 401을 낸다.
- **연결 확인**: `GET /api/nr-plans/ping`은 같은 토큰으로 `{"ok": true}`를 돌려준다. 확장 프로그램 설정의 "연결 테스트"가 쓴다.
- **크기 제한**: 한 번에 200행, 본문 1MB. 넘으면 413.

요청 본문:

```json
{
  "rows": [
    {
      "key": "2026-12345",
      "org": "전라북도 완주군",
      "name": "완주군 다목적체육관",
      "addr": "전북특별자치도 완주군 봉동읍 …",
      "start": "2027-03-01",
      "end": "2028-06-30",
      "dept": "체육진흥과",
      "energy": [{"source": "지열", "form": "수직밀폐형", "capacity_kw": 336.06}]
    }
  ]
}
```

- `key`는 확장 프로그램의 작업 기록 키를 그대로 쓴다. 신청번호이고 작성중인 건은 기관명+건물명이다. 같은 `key`가 다시 오면 덮어쓴다.
- 응답은 행마다 `created | updated | unchanged | invalid`와 짝 찾기 결과(`linked | new_project | pending`)를 돌려준다. 잘못된 행은 그 행만 `invalid`로 돌려주고 나머지는 처리한다.
- 날짜는 `YYYY-MM-DD`만 받는다. 용량은 0보다 큰 유한한 수만 받는다. 기존 `edit._positive`와 같은 규칙이다.

## 4. 데이터

### 4.1 `nr_plan` (새 표)

| 칸 | 내용 |
|---|---|
| `key` | 확장 프로그램 작업 기록 키. UNIQUE |
| `org_name`, `building_name`, `address`, `start_date`, `end_date`, `dept` | 받은 원문 |
| `energy_json` | `[{source, form, capacity_kw}]` |
| `received_at`, `updated_at` | 처음 받은 때, 마지막으로 바뀐 때 |
| `project_id` | 연결된 사업. 없으면 NULL |
| `match_state` | `auto`(자동 연결) · `new`(새 사업 추가) · `pending`(사람 확인 필요) · `human`(사람이 연결) · `ignored`(무시) |
| `match_score` | 자동 연결·후보 점수 (0~1) |

`human`·`ignored` 행은 다시 받아도 짝을 다시 찾지 않는다. 원문만 갱신하고 `human`이면 연결된 사업에 다시 반영한다.

### 4.2 에너지원·형식 목록 (`energy_kind`, 새 표 — 1장 4번 권장안)

| 칸 | 내용 |
|---|---|
| `code` | 저장 이름. 기존 6종은 `PV`·`BIPV`·`집광채광`·`지열`·`PEMFC`·`SOFC` 그대로, 새 종류는 `"{에너지원} {형식}"` |
| `source`, `form`, `sort` | 에너지원, 형식, 화면 순서 |

- 기존 6종을 시드로 넣는다. `nara/energy.py`의 `ENERGY_KINDS` 상수는 이 표를 읽는 함수로 바꾼다. 시트 이관용 `parse_energy_plan`은 그대로 둔다.
- 새 종류는 단가 없이 들어온다. 단가 관리 화면에 "단가 없음"으로 보이고 단가를 넣으면 `energy_unit_price`에 행이 생긴다.

### 4.3 기존 표에 더하는 값

- `energy_plan.entered_by`에 `'nr'`을 더한다.
- `dept_check.decided_by`에 `'nr'`을 더한다. 화면 라벨은 "설치계획서"다.
- `project.source`에 `'nr'`을 더한다. 설치계획서로 새로 만든 사업이다.

## 5. 짝 찾기 (`nara/nr_match.py`, 순수 함수)

**기관 정규화** — 실측 결과 관심기관 71곳 중 이름이 똑같은 곳은 16곳뿐이다.

1. 공백을 없앤다.
2. 옛 행정구역 이름을 바꾼다: `전라북도`→`전북특별자치도`, `강원도`→`강원특별자치도`, `제주도`→`제주특별자치도`.
3. 시·군·구 뒤의 `청`을 뗀다: `서초구청`→`서초구`.
4. 예외는 `config.toml [nr] org_aliases`에 적는다.

**이름 점수**

- 사업명에서 조달 용어 꼬리를 뗀다. `status.py`의 `_QUERY_MARKERS` 규칙을 함께 쓴다.
- 양쪽의 공백과 괄호를 없앤 뒤, 한쪽이 다른 쪽을 포함하면 0.9점이다. 아니면 두 글자 단위 자카드 유사도를 쓴다.
- 주소의 시·군·구와 도로명이 같으면 +0.1점이다.

**판정** — 같은 기관(정규화 후)의 사업만 후보로 본다. 숨긴 사업도 후보에 넣는다.

| 조건 | 결과 |
|---|---|
| 1등 ≥ 0.8 이고 2등과 0.2 이상 차이 | 자동 연결 (`auto`) |
| 후보가 없거나 1등 < 0.4 | 새 사업 추가 (`new`) |
| 그 사이 | 사람 확인 (`pending`) |

임계값은 상수로 두고 실제 설치계획 자료로 맞춘 테스트(정답표)로 정한다. 정답표 방식은 실행부서 찾기 때와 같다.

**새 사업**: 기관은 정규화한 이름으로 `upsert_org`(관심기관 규칙은 기존 그대로), 사업명은 건물명, `source='nr'`이다.

## 6. 반영 (`nara/nr_apply.py`)

| 항목 | 반영 방법 | 지키는 값 |
|---|---|---|
| 신재생 계획 | 그 사업의 줄을 설치계획서 줄로 바꾼다 (`entered_by='nr'`) | 웹에서 고친 적이 있으면(`edited_on_web(…, "energy")`) 건너뛴다 |
| 착공일·준공일·주소 | 설치계획서 값으로 바꾼다 | 칸마다 웹 수정이 있으면 건너뛴다 |
| 실행부서 | `dept_check`에 `decided_by='nr'`, `confirmed=1`로 쌓는다. 근거 문장은 "설치계획서 의무기관 담당자 부서" | 최신 부서가 사람 판정이면 건너뛴다 |

- 확정 부서가 생기므로 그 사업은 실행부서 찾기 대상에서 빠진다. 첨부 다운로드와 Claude 호출이 줄어든다.
- 숨긴 사업에도 반영한다. 숨김은 풀지 않는다.
- 건너뛴 칸은 `nr_plan` 행에 기록하고 연결 화면에 "웹에서 고친 값이 있어 반영하지 않음"으로 보인다.
- 한 번 받은 요청은 `run_log`(`command='nr import'`)에 건수를 남긴다.

## 7. 화면

- **설치계획 화면(`/nr`)**: 받은 설치계획을 상태별(확인 필요·자동 연결·새 사업·사람 연결·무시)로 나열한다. 위쪽 메뉴에 링크를 둔다.
  - `pending` 행: 후보 사업과 점수를 보이고 [이 사업과 연결] [새 사업으로 추가] [무시] 버튼을 둔다.
  - 자동 연결·새 사업 행: [연결 바꾸기]로 잘못 붙은 것을 고친다. 바꾸면 `human`이 된다.
- **사업 상세**: "설치계획서" 칸에 원문(받은 때, 신청번호, 담당부서, 에너지원)을 보인다.
- **목록**: "확인 필요 N건"이 있으면 머리에 링크를 둔다.

## 8. 확장 프로그램 변경 (다른 저장소)

- 설정 페이지에 "5. 나라 앱으로 보내기"를 둔다: 나라 앱 주소, 토큰, [연결 테스트].
- 나라 앱 주소는 `optional_host_permissions`로 그때그때 권한을 받는다. `http://127.0.0.1:8000/*`, 사내망 주소, https 주소를 모두 받을 수 있게 한다.
- 크롤링 한 건을 마칠 때마다 background에서 받는 주소로 보낸다. 시트 연결이 있으면 시트에도 그대로 쓴다.
- 에너지원은 문자열과 함께 구조화된 배열(`source`·`form`·`capacity_kw`)로 보낸다.
- 지금의 제외 규칙(일정 없음·준공일 지남)은 그대로 둔다. 시트에 쓰는 행과 나라 앱에 보내는 행을 같게 한다.
- 버전을 1.5.0으로 올리고 `test/run-crawl.mjs`에 보내기 시험을 더한다.

## 9. 보안

- 토큰은 `.env`와 확장 프로그램 저장소에만 둔다. 두 저장소 모두 공개이므로 코드·테스트에 실제 값을 넣지 않는다.
- 받는 주소는 로그인 없이 열리므로 토큰이 유일한 인증 수단이다. 토큰 비교는 상수 시간으로 하고 실패는 run_log에 남기되 토큰 값은 남기지 않는다.
- 받은 문자열은 길이를 자른다(`TEXT_LIMIT`). 화면에서는 지금과 같은 방식으로 이스케이프한다.

## 10. 단계

각 단계는 따로 병합할 수 있다.

| 단계 | 내용 | 끝났다는 기준 |
|---|---|---|
| 1 | `energy_kind` 표로 옮기기 (기존 화면 동작 그대로) | 기존 테스트 통과, 새 종류 추가 시험 |
| 2 | 받는 주소 + `nr_plan` 저장 | 토큰 없음·틀림 401, 같은 key 재전송 시 `unchanged` |
| 3 | 짝 찾기 + 반영 + 새 사업 추가 | 정답표 시험, 웹 수정 보존 시험 |
| 4 | 설치계획 화면, 상세 칸 | 연결·새 사업·무시·연결 바꾸기 시험 |
| 5 | 확장 프로그램 변경 (다른 저장소) | 실제 사이트에서 몇 건 보내 나라 앱 화면에서 확인 |

## 11. 테스트 의도

- 토큰이 없거나 틀리면 아무것도 쓰지 않는다.
- 같은 설치계획을 두 번 보내도 사업·신재생 줄·부서 기록이 한 벌이다.
- 사람이 연결하거나 무시한 건은 다시 받아도 짝을 다시 찾지 않는다.
- 사람이 웹에서 고친 신재생 계획·날짜·주소·부서는 설치계획서가 덮지 않는다.
- `전라북도 완주군`·`서울특별시 서초구청`이 나라 앱의 기관과 짝을 찾는다.
- 6종에 없는 에너지원이 오면 단가 없이 목록에 생기고 합계 옆에 "단가 없음"으로 나온다.
