# 웹 설정 화면 설계

## 요약

- **주제**: 수집 키워드·관심기관·설치계획서 기관 별칭을 웹 설정 화면에서 보고 고친다.
- **배경**: 지금 이 값들은 `config.toml`에 있다. 바꾸려면 파일을 고치고 커밋한 뒤 서버를 다시 띄워야 한다. 파일 머리 주석은 스프레드시트 `설정` 탭을 정본이라 하지만, 실제로는 시트에 반영되지 않은 변경이 여럿 쌓였다(2026-10-01 키워드, 서울·부산 관심기관). 또 키워드를 더해도 이미 수집된 사업에는 적용되지 않는다.
- **결론**: 설정을 DB로 옮기고 정본을 웹 설정 화면 하나로 정한다. 저장하기 전에 확인 화면에서 이미 모은 데이터에 미칠 영향을 보여 준다. 숨길 사업은 사람이 체크해서 고르고, 관심기관은 확인 후 올리거나 내린다. 저장한 값은 서버를 다시 띄우지 않아도 다음 수집부터 쓰인다.

## 1. 정한 것

| 항목 | 결정 | 근거 |
|---|---|---|
| 관리 범위 | 제목 필수·제외 키워드, 기관 제외 키워드, 관심기관(포함·정확), 설치계획서 기관 별칭 | 사용자 선택(2026-10-09) |
| 저장 위치 | DB 표 (A안) | 서버를 다시 띄우지 않아도 반영되고 변경 기록이 남는다. 공개 저장소의 `config.toml`을 웹이 고치지 않는다 |
| 정본 | 웹 설정 화면 | 사용자 결정(2026-10-09). 시트 `설정` 탭과 `config.toml` 목록은 더 이상 정본이 아니다 |
| 제외 키워드를 더할 때 기존 사업 | 확인 화면에 걸리는 사업을 보여 주고 체크한 것만 숨김 | 사용자 선택. 키워드가 엉뚱한 사업을 잡을 수 있다(예: '보도'가 '정보도서관'에 걸림) |
| 관심기관을 뺄 때 기존 기관 | 확인 화면에 빠질 기관을 보여 주고 확인하면 일반 기관으로 내림 | 사용자 선택 |
| 웹에서 관리하지 않는 값 | `service_div_name`, `skip_cancelled`는 `config.toml`에 남김 | 나라장터 API 동작 값이라 바꿀 일이 거의 없다 |
| 고칠 수 있는 사람 | 로그인한 사람 모두 | 계정에 관리자 구분이 없다. 대신 누가 무엇을 바꿨는지 남긴다 |

## 2. 저장 구조

### 2.1 표

```sql
-- 웹 설정 화면이 정본. 처음 한 번만 config.toml 목록을 옮겨 채운다.
CREATE TABLE IF NOT EXISTS setting_item (
  kind      TEXT NOT NULL,   -- title_required | title_excluded | org_excluded
                             -- | focus_org | focus_exact_org | nr_alias
  value     TEXT NOT NULL,   -- 키워드·기관명. nr_alias면 설치계획서 쪽 기관명
  target    TEXT,            -- nr_alias일 때만: 나라 앱 기관명
  added_at  TEXT NOT NULL,
  added_by  INTEGER REFERENCES app_user(id),
  PRIMARY KEY (kind, value)
);

CREATE TABLE IF NOT EXISTS setting_log (
  id        INTEGER PRIMARY KEY,
  at        TEXT NOT NULL,
  user_id   INTEGER REFERENCES app_user(id),
  kind      TEXT NOT NULL,
  action    TEXT NOT NULL,   -- add | remove | seed
  value     TEXT NOT NULL,
  target    TEXT
);
```

### 2.2 처음 옮기기 (seed)

- `app_state`에 `settings_seeded`가 없으면 `config.toml`의 목록을 `setting_item`에 넣는다. 그다음 `settings_seeded`를 남긴다. `setting_log`에는 `action = 'seed'`로 한 줄씩 기록한다.
- 이 표시가 있으면 다시 옮기지 않는다. 웹에서 목록을 전부 비워도 파일 값으로 되살아나지 않는다.
- 옮기는 때는 설정을 처음 읽는 순간이다(아래 2.3). 수집·예약 실행·서버 중 누가 먼저 돌든 결과는 같다.

### 2.3 읽기

`nara/settings_store.py`(새 파일):

| 함수 | 하는 일 |
|---|---|
| `current_settings(conn, base: Settings) -> Settings` | 필요하면 2.2대로 옮기고, DB 목록으로 `base`의 목록 칸을 바꾼 `Settings`를 돌려준다. `service_div_name`·`skip_cancelled`는 `base` 값 그대로 |
| `items(conn, kind) -> list[Row]` | 설정 화면용 목록 |
| `plan_change(conn, base, adds, removes) -> ChangePlan` | 저장 전 미리보기(3장). DB를 바꾸지 않는다 |
| `apply_change(conn, plan, hide_ids, user_id, now)` | 설정 변경·숨김·관심 조정을 한 트랜잭션으로 반영 |

`Settings` 데이터 모양은 바꾸지 않는다. 필터·매칭 코드는 지금과 같이 `Settings`만 받는다.

| 쓰는 곳 | 읽는 때 |
|---|---|
| `nara collect`·`backfill`·`run slot`·`enrich *` | 명령 시작 때 한 번 |
| 웹 서버(설치계획서 받기·연결·새 사업) | 요청마다(목록이 수백 줄이라 부담 없음) |

`config.toml` 머리 주석은 "목록은 처음 한 번 DB로 옮기는 초기값이다. 정본은 웹 설정 화면이다"로 바꾼다. 목록 자체는 남겨 둔다. 테스트가 이 값을 기준 설정으로 쓰고, 새 DB를 만들 때 초기값이 된다.

## 3. 저장 전 확인 화면

설정 화면에서 "저장"을 누르면 바로 반영하지 않는다. 바뀌는 값과 그 영향을 먼저 보여 준다.

### 3.1 바뀌는 값

종류별로 더한 값과 뺀 값을 보여 준다(예: "더함: 감리, 소방 / 뺌: 도로").

### 3.2 숨길 사업 후보 (제목·기관 규칙이 좁아질 때)

| 경우 | 후보 |
|---|---|
| 제목 제외 키워드를 더함 / 제목 필수 키워드를 뺌 | 숨기지 않은 사업 중 공고가 있고, 바뀌기 전 설정으로는 공고 제목이 하나 이상 통과했지만 바뀐 뒤에는 하나도 통과하지 못하는 사업 |
| 기관 제외 키워드를 더함 | 숨기지 않은 사업 중 기관명이 새 키워드에 걸리는 사업 |

- 공고가 없는 사업(시트 이관·설치계획서로 만든 사업)은 제목 규칙으로 고르지 않는다. 처음부터 제목 필터를 거쳐 들어온 사업이 아니다.
- 후보마다 체크박스가 있고 기본값은 **체크 안 함**이다. "모두 선택"은 둔다.
- 후보마다 걸린 키워드를 보여 준다. 숨김 사유는 `설정 변경: 제외 키워드 '감리'` 꼴로 남긴다. 숨긴 사업은 기존 "숨긴 사업" 화면에서 되돌린다.

### 3.3 관심기관 조정

| 경우 | 동작 |
|---|---|
| 바뀐 설정으로 관심이 아니게 되는 관심 기관 | "관심에서 빠질 기관 N곳(사업 M건)"으로 보여 준다. 확인 저장하면 `tier = 'rest'`, `weekday_group = id % 5 + 1`(신규 등록과 같은 규칙) |
| 바뀐 설정으로 관심이 되는 일반 기관 | "관심으로 올릴 기관 N곳"으로 보여 준다. 확인 저장하면 `tier = 'focus'`, `weekday_group = NULL` |

기관을 내려도 사업·공고·판정 기록은 그대로다. 조회 주기만 매일에서 요일별로 바뀐다.

### 3.4 넓어지는 변경

제목 제외 키워드를 빼거나 기관 제외 키워드를 빼면, 전에 걸러진 공고는 DB에 없다. 확인 화면에 "전에 걸러진 공고는 다시 수집해야 들어옵니다(`nara backfill`)"라고 알린다. 자동으로 다시 수집하지는 않는다.

### 3.5 확인 저장

- "확인 저장"은 설정 변경, 체크한 사업 숨김, 관심 조정, `setting_log` 기록을 **한 트랜잭션**으로 처리한다. 하나라도 실패하면 전부 되돌린다.
- 확인 화면을 띄운 뒤 다른 사람이 설정을 바꿨으면 저장을 거부한다. 판정은 확인 화면에 숨겨 둔 변경 전 목록의 해시로 한다. "그사이 설정이 바뀌었습니다. 다시 확인하세요"로 확인 화면을 새로 그린다.
- 바뀐 것이 없으면 확인 화면 없이 "바뀐 것이 없습니다"를 띄운다.

## 4. 설정 화면

- 주소 `/settings`. 상단 메뉴 "단가 관리" 옆에 "설정"을 둔다.
- 칸 5개를 둔다.
  1. 제목 필수 키워드
  2. 제목 제외 키워드
  3. 기관 제외 키워드
  4. 관심기관: 이름에 포함 / 이름이 정확히 같음 두 목록
  5. 설치계획서 기관 별칭: 설치계획서 기관명 → 나라 앱 기관명
- 각 칸에서 할 수 있는 일:
  - 지금 값을 목록으로 보고, 뺄 값에 체크한다.
  - 더할 값을 줄마다 하나씩 적는다. 별칭은 `설치계획서 기관명 = 나라 앱 기관명` 꼴로 적는다.
  - 칸마다 값 개수를 보여 주고, 목록이 길면 검색창으로 거른다(수요기관 고르기와 같은 방식).
- 화면 아래에 최근 변경 기록 50줄을 보여 준다(때·사람·종류·더함/뺌·값).

### 4.1 입력 검사

| 규칙 | 오류 문구 |
|---|---|
| 앞뒤 공백 제거, 빈 줄 무시, 같은 값 중복 무시 | (오류 아님) |
| 키워드는 2자 이상 | "키워드는 2자 이상이어야 합니다: 감" |
| 값은 50자 이하 | "50자까지 적을 수 있습니다" |
| 이미 있는 값을 더함 | (오류 아님, 무시) |
| 별칭 줄에 `=`가 없거나 한쪽이 비었음 | "`설치계획서 기관명 = 나라 앱 기관명` 꼴로 적으세요" |
| 제목 필수 키워드를 전부 뺌 | "제목 필수 키워드가 없으면 모든 용역을 수집합니다" 경고만 하고 막지 않는다 |

오류가 있으면 입력한 값을 그대로 둔 채 422로 다시 그린다.

### 4.2 안전

- 쓰기 요청은 기존 `_guard_writes`(다른 사이트에서 보낸 요청 차단)를 그대로 거친다.
- DB가 잠겼으면 기존 `BUSY_MESSAGE`로 503을 낸다.
- 설정 화면은 로그인이 필요하다. 토큰으로 여는 예외(설치계획서 받는 주소에 있는 것)는 두지 않는다.

## 5. 테스트

| 테스트 | 왜 중요한가 |
|---|---|
| 처음 읽을 때 `config.toml` 목록이 DB로 옮겨지고, 두 번 읽어도 늘지 않는다 | 실행할 때마다 중복되면 키워드가 끝없이 늘어난다 |
| 웹에서 목록을 비운 뒤 다시 읽어도 파일 값이 돌아오지 않는다 | 정본이 웹이라는 결정을 지킨다 |
| 웹에서 제외 키워드를 더하면 다음 `collect`가 그 공고를 거른다 | 서버를 다시 띄우지 않아도 반영된다는 약속 |
| 확인 화면 후보는 바뀌기 전에는 통과하고 바뀐 뒤 막히는 사업만 담는다 | 이미 다른 이유로 걸린 사업까지 끌어오지 않는다 |
| 확인 저장은 체크한 사업만 숨기고 사유에 키워드를 남긴다 | 엉뚱하게 걸린 사업을 사람이 빼낼 수 있어야 한다 |
| 관심기관 이름을 빼면 해당 기관이 일반으로 내려가고 요일 그룹이 생긴다 | 내려간 기관이 어느 요일에도 조회되지 않는 일을 막는다 |
| 관심기관 이름을 더하면 일반 기관이 관심으로 올라간다 | 기존 승격 규칙과 같게 동작한다 |
| 확인 화면 뒤 설정이 바뀌면 저장을 거부한다 | 두 사람이 동시에 고칠 때 한쪽 변경이 조용히 사라지지 않게 한다 |
| 입력 검사 오류는 422로 값을 유지한 채 다시 그린다 | 긴 목록을 다시 적게 하지 않는다 |
| 다른 사이트에서 보낸 저장 요청은 403 | 기존 쓰기 화면과 같은 보호 |
| 저장 중 하나가 실패하면 설정·숨김·관심 조정이 모두 그대로다 | 반쯤 바뀐 설정이 남지 않는다 |
| 설치계획서 별칭을 웹에서 더하면 다음 설치계획서 받기에 쓰인다 | 웹 서버가 요청마다 읽는다는 약속 |

기존 테스트 786건은 그대로 통과해야 한다.

## 6. 범위 밖

- 시트 `설정` 탭과의 자동 동기화. 시트는 더 이상 정본이 아니다.
- 키워드 변경으로 걸러졌던 공고를 자동으로 다시 수집하는 것(3.4 안내만 한다).
- 관리자 권한 구분.
- `service_div_name`·`skip_cancelled`의 웹 편집.
