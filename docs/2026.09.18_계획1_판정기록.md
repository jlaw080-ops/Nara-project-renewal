## 실행 전 판정

Ruling R1: `uv init --package`를 쓰지 않고 pyproject.toml을 직접 쓴다 — uv 0.12.5로
실측하니 `src/nara/` 배치와 `uv_build` 백엔드를 만드는데 계획의 모든 경로가 평면
`nara/`를 전제하고, 기존 .gitignore도 건드린다. `[tool.uv.build-backend] module-root = ""`
한 줄로 평면 배치를 유지한다. T5의 hatch 설정은 백엔드가 달라 무효였으므로 삭제.
비용: 틀렸다면 Task 1에서 ModuleNotFoundError로 즉시 드러난다.

Ruling R2: T3 테스트의 관심기관 19개 단언은 Step 1의 "원본을 따른다"와 충돌한다.
확인 대상을 "목록이 잘리지 않았다"로 고치고, 원본 개수가 다르면 숫자를 원본에 맞춰
고치되 무엇이 달랐는지 커밋 메시지에 적게 했다. 제외어 60개 이상 단언도 추가.
비용: 원본과 다른 개수가 조용히 통과할 수 있다 — 커밋 메시지가 근거로 남는다.

Ruling R3: T4의 단일 케이스 parametrize 두 개에 쓰이지 않는 `reason` 인자가 있었다.
평범한 테스트 함수로 풀고 이름에 무엇을 검증하는지 적었다. 비용: 없음.

Ruling R4: T13 대조식이 `rows == notices + projects + skipped`였는데 notices/projects는
**신규** 건수라 같은 탭을 다시 넣으면 0이 되어 정상 재실행이 대조 실패로 뜬다.
`imported` 카운터를 두고 `rows == imported + skipped`로 바꿨다. 재실행 테스트 추가.
비용: 없음 — 없었다면 이관을 두 번 돌릴 때마다 exit 1이었다.

Ruling R5: T9가 collect.py에 `from datetime import date, timedelta` 줄을 새로 만들어
T8의 `from datetime import datetime`과 중복됐다. 기존 줄을 넓히라고 명시.
비용: 없음.

Ruling R6: T15의 커버리지 80% 게이트는 cli.py 때문에 못 넘길 수 있다. 모자라면
CliRunner 테스트를 더하라고 적고, 커버리지 설정에서 cli.py를 빼는 회피를 금지했다.
