## 0. 한 줄 요약

**화면의 겉모습만 바꾼다.** 기능·주소(URL)·폼 필드 이름·파이썬 로직은 그대로 두고, Jinja 템플릿과 CSS만 디자인 시안대로 바꾼다. 화면 하나씩 바꾸고, 바꿀 때마다 테스트를 통과시키고 커밋한다.

## 1. 참고 자료 (이 폴더 안)

| 파일 | 무엇 |
|---|---|
| `design-system.md` | 디자인 규칙 전체 (색 · 글자 · 간격 · 문구 규칙 · 화면별 설명). **먼저 읽는다.** |
| `tokens.css` | 색 · 간격 · 모서리 · 글꼴 변수(`--primary` 등) + Pretendard `@font-face` |

## 2. 꼭 지킬 규칙

1. **바꾸지 않는 것**: `nara/` 아래 `.py` 파일의 동작, 라우트와 URL, `<form>`의 `method`·`action`, 모든 `name=` 속성, hidden input(`version`, `next`, `fingerprint` 등), 쿼리 파라미터 이름, 화면 문구(버튼·안내 문장). 파이썬은 템플릿에 값을 넘기는 데 꼭 필요할 때만 최소로 고치고, 고쳤다면 그 이유를 커밋 메시지에 적는다.
2. **새 라이브러리 금지**: React · Tailwind · 빌드 도구를 들이지 않는다. 순수 HTML + CSS, 필요한 곳만 짧은 바닐라 JavaScript(지금 템플릿에 있는 방식).
3. **값은 변수로만**: 색 · 간격은 `tokens.css` 변수로 쓴다. 템플릿 안 `style="…"`에 색 값을 직접 쓰지 않는다.
4. **JavaScript 없이도 동작**: 칩 · 펼침 메뉴 · 일괄 작업 줄은 꾸밈이다. JS가 꺼져도 폼 제출은 지금처럼 되어야 한다.
5. **테스트**: 단계마다 `uv run pytest`와 `uv run ruff check .`가 통과해야 한다. 일부 테스트는 마크업을 직접 검사한다 — 아래 6장. 테스트를 고쳐야 한다면 **기능 검사는 그대로 두고 마크업 문자열만** 바꾸고, 커밋 메시지에 어떤 테스트를 왜 고쳤는지 적는다.
6. **단계마다 커밋**, 한 단계가 끝나면 멈추고 무엇을 바꿨는지 보고한다.

## 3. 작업 단계

### 단계 0 — 준비

- 새 브랜치 `ui-v2`에서 작업한다.
- 이 폴더가 저장소의 `docs/design/`에 있는지 확인한다.
- 정적 파일 자리 만들기 (Flask 기본 `static` 폴더, 이미 로그인 없이 열리게 되어 있다 — `PUBLIC_ENDPOINTS`의 `"static"`):
  - `nara/web/static/css/tokens.css` ← `docs/design/tokens.css` 복사. 글꼴 경로를 `url("../fonts/…")`로 고친다.
  - `nara/web/static/css/nara.css` ← `docs/design/nara.css` 복사
  - `nara/web/static/fonts/` ← `docs/design/fonts/*.woff2` 복사
- `pyproject.toml`의 패키지 설정이 `static/` 파일을 함께 싣는지 확인한다(템플릿이 실리는 방식과 같게). 서버 배포(`deploy/`)에서도 정적 파일이 나가는지 확인한다.
- 커밋: `chore: UI v2 디자인 자료와 정적 파일 자리`

### 단계 1 — 공통 틀 (`base.html`)

- `<style>` 블록을 지우고 `<link>`로 `tokens.css`, `nara.css`를 건다(`url_for('static', filename=…)`).
- 상단 링크 줄 → `components/AppBar.html` 마크업.
  - 메뉴: 사업 조회 · 설치계획 · 단가 관리 · 설정. 현재 화면 메뉴에 `aria-current="page"` — 템플릿에서 `request.endpoint`로 정한다(상세 화면은 "사업 조회", 설치계획 상세는 "설치계획").
  - 오른쪽: 신재생에너지센터 ↗ 링크(기존 href · target · rel · title 그대로), 사용자 이름, 비밀번호 바꾸기 링크, 로그아웃 POST 폼(버튼은 `.btn btn--sm btn--quiet`, 앱 바 위에서 읽히게 흰 글자).
  - 로그인 전(`g.user` 없음)에는 앱 이름만.
- 본문을 `<main class="page">`로 감싼다.
- flash 메시지 `.saved` → `.notice notice--success`(제목 "알림"), 기존 문장 그대로.
- 남은 화면이 깨지지 않도록 옛 클래스(`.muted`, `.bad`, `.saved`, `.field-error`, `.table-wrap`, `.edit-form`, `form.inline` 등)를 `nara.css` 끝에 **임시 호환 구역**으로 새 디자인에 맞게 정의해 둔다. 마지막 단계에서 지운다.
- 확인: 모든 화면이 열리고, 로그인 · 로그아웃이 된다.

### 단계 2 — 사업 조회 (`list.html`) ← `screens/ListScreen.html`

- 머리: 제목 + 실행 상태 줄(`.runs`/`.run`, 실패는 `.run--fail`), 오른쪽에 "지금 조회" select + "지금 실행"(작은 보조 버튼). 폼은 그대로.
- "설치계획 확인 필요 N건" → `.notice` + 오른쪽 링크.
- 조건 패널(`.panel` 안 `form.filters`, GET 그대로):
  - 수요기관: `<details class="picker">` 펼침 안에 기존 검색칸 · 모두 선택 · 선택 해제 · 체크박스 목록(`name="org"`)을 그대로 옮긴다. 펼침 단추 글자는 "N곳 선택"/"전체".
  - 이름 검색 · 공고일 시작/끝: `.field` + `.input`.
  - 진행현황: 여러 줄 `<select multiple name="verdict">` → **같은 이름의 체크박스 여러 개**(`name="verdict" value="…"`)를 칩 모양(`.chip`)으로. 서버는 `getlist`로 읽으므로 그대로 동작한다. 관심기관만(`focus`) · 실행부서 검토 필요(`dept=review`) · 숨긴 사업만(`hidden`)도 같은 칩 줄.
  - 칩은 `<label class="chip"><input type="checkbox" …> 글자</label>` 구조로 만들고, 체크박스는 화면에서 숨기되 키보드로 고를 수 있게 한다(`:has(input:checked)`로 켜진 모양).
  - 오른쪽 끝 "조건 지우기"(조용한) · "조회"(주).
- 결과 패널(`.panel panel--flush`):
  - `.resultbar`: "N건 중 M건", 조건, 오른쪽에 PDF로 출력 · 엑셀로 받기(작은 보조 버튼, 기존 href 그대로).
  - 숨기기 폼(`#hide-form`, `pid` · `hide_reason` · `next`)은 그대로. 숨기기 줄을 `.bulkbar`로 바꾸고, **체크한 행이 있을 때만** 보이게 JS로 토글한다(JS가 없으면 늘 보임). "N건 고름" 글자를 갱신한다.
  - 표: `.table`, 사업명은 `.title` 링크 + `.sub` 공고명, 날짜 칸 `.col-date`.
  - 진행현황 칸 → `.badge` (값 → 클래스: 착공 전(설계 단계) `badge--before`, 시공 중 `badge--building`, 준공 완료 `badge--done`, 미확인 `badge--unknown`, 판정 전 `badge--none`). 매핑은 Jinja 매크로 하나로 만들어 모든 화면에서 같이 쓴다(`templates/_macros.html`). 사람이 정한 값의 "(사람)" → `<span class="by-human">수동</span>`.
  - 실행부서 "검토 필요" → `.badge badge--none`.
  - 체크한 행에 `aria-selected="true"`(JS).
- 확인: 정렬 · 필터 조합 · 숨기기/숨김 풀기 · PDF · 엑셀이 전과 똑같이 된다.

### 단계 3 — 사업 상세 (`detail.html`) ← `screens/DetailScreen.html`, `DetailEdit.html`

- "← 목록으로" → `.crumb` "← 사업 조회 목록" (기존 href · `list_query` 그대로).
- 요약 패널 `.detail-head`: 사업명, 수요기관 · 출처 · 진행현황 배지(+수동), 오른쪽에 "이 사업 다시 조회"(보조) · 숨기기(조용한, 숨기는 이유 입력은 누르면 펼쳐지는 `<details>` 안으로). 숨긴 사업이면 그 자리에 숨김 안내 `.notice` + "숨김 풀기". 다시 조회 상태는 `.runs`.
- 핵심 숫자 줄 `.facts`: 공고일 · 개찰일 · 예산(첫 공고) · 낙찰업체 · 실행부서 · 신재생 설치비 합계. 이미 템플릿에 넘어오는 값으로 만든다.
- 구역 탭 `.tabs`: 각 구역 `id`로 가는 페이지 안 링크 + 건수.
- 두 칸 `.split`:
  - 왼쪽 `.stack`: 사업(정의 목록 `.dl`) · 공고(표 + 첨부 `.files`/`.file`, 확장자 배지) · 진행현황 이력(사람 판정 잠금 안내는 `.notice` + "자동 판정에 다시 맡기기" 보조 버튼) · 신재생 계획(표 + `.sum` 합계, 단가 없어 빠진 항목은 `.notice notice--warning`).
  - 오른쪽 `.split__side`: 실행부서(부서명 + 확정/후보 배지, 부서장 · 실무 담당자 `.person`, 전화번호는 `tel:` 링크, 공고문에서 읽은 값은 `.auto` "공고문", 조회 기록 표는 `<details>`로 접기) · 설치계획서 · 수정 이력(최근 3건 `.log`, 나머지는 "모두 보기" `<details>`).
- 각 구역 머리 `.section-head`의 "고치기"는 기존 `edit_link` 매크로 링크를 `.btn btn--sm btn--quiet` 모양으로.
- 고치기 상태(`edit == '…'`): 그 구역 패널에 `.panel--editing`, 입력은 `.form-grid` + `.field`, 실행부서 후보는 `.candidate` 카드(라디오 `name="pick"` 그대로), 오류는 `.field__error` + `aria-invalid="true"`, 아래 `.form-actions`에 취소(조용한) · 저장(주). 신재생 계획 편집의 기존 JS(형식 거르기 · 설치비 계산)는 클래스 이름을 유지해 그대로 동작하게 한다.
- 확인: 일곱 구역 보기 · 네 구역 고치기 · 저장 충돌(version) · 오류 표시 · 자동 판정 되돌리기 · 숨기기가 전과 같다.

### 단계 4 — 설치계획 (`nr_list.html`, `nr_detail.html`)

- 목록 ← `screens/NrListScreen.html`: 상태 링크 줄 → `.segmented`(현재 상태 `aria-current="page"`, "확인 필요" 건수는 `.n--alert`). 점수 칸 → `.meter`(0.5 미만은 `.meter--low`) + 소수 둘째 자리. 연결 안 된 행 끝에 상세로 가는 "연결하기"(작은 보조 버튼).
- 상세 ← `screens/NrDetailScreen.html`: 요약 패널(건물명 · 기관 · 신청번호 · 상태 배지, "무시"는 오른쪽 위 조용한 버튼 — 기존 POST 폼 그대로) + `.facts`. 왼쪽 "연결할 사업 고르기": 후보마다 `.match`(점수 높은 첫 후보 `.match--best` + 주 버튼, 나머지 보조 버튼 · 기존 POST 폼 그대로). `.or` 구분선 아래 사업 번호로 연결 · 새 사업으로 추가. 오른쪽 설치계획서 내용(`.dl` + 에너지원 표). 후보 카드의 진행현황 · 실행부서 · 신재생 계획은 템플릿에 값이 없으면 생략한다(파이썬을 늘리지 않는다).

### 단계 5 — 단가 관리 (`prices.html`) ← `screens/PricesScreen.html`

- 에너지원별 묶음 행(`.group-row`) + 형식별 행, 단가 칸 `.input input--num input--cell`(`name="code"` · `name="price"` 순서 그대로).
- 단가 없는 형식: `.badge badge--fail` "단가 없음", 하나라도 있으면 위에 `.notice notice--warning`.
- JS: 값이 처음과 달라진 행에 `.is-changed` + 이전 값 `.was`, 하나라도 바뀌면 아래 `.savebar`("단가 N개를 고쳤습니다" · 되돌리기 · 저장)를 보인다. JS가 없으면 저장 버튼이 늘 보이게 한다. 영향 건수 문장은 서버가 값을 주지 않으면 빼고 "저장하면 모든 사업의 설치비가 다시 계산됩니다"로 쓴다.

### 단계 6 — 설정 (`settings.html`, `settings_preview.html`)

- 설정 ← `screens/SettingsScreen.html`:
  - 한 `<form>`에 여섯 종류가 다 들어 있는 구조는 **그대로** 둔다. 왼쪽 `.sidenav`는 종류 사이를 오가는 탭(JS로 하나만 보이기, JS가 없으면 모두 보이고 `.sidenav`는 페이지 안 링크).
  - 값 목록 → `.values`/`.value` 칩. 칩은 `<label class="value">값 <input type="checkbox" name="remove_{kind}" value="…"> ×</label>` 구조 — 체크하면 `.value--remove`(빨간 취소선). 기존 검색칸은 `class="setting-search"`를 유지한다(테스트가 검사).
  - "더할 값" textarea(`name="add_{kind}"`) 그대로. 입력한 줄은 위 칩 줄 끝에 `.value--add`로 미리 보이게(JS, 선택 사항).
  - 아래 `.savebar`: "뺄 값 N개 · 더할 값 N개" · 되돌리기 · "저장 (확인 화면으로)".
  - 최근 변경 표: "더함/뺌"을 `.badge badge--done` / `.badge badge--fail`로.
- 설정 변경 확인 ← `screens/SettingsConfirm.html`:
  - "바뀌는 값" → `.diff` + `.value--add`(+) / `.value--remove`(−).
  - 영향 → `.impact` 카드(걸리는 사업 수 · 관심에서 빠질/오를 기관 수 · 다시 수집 필요 여부). 기존 경고(`warnings`, `message`)는 `.notice notice--warning`/`--danger`.
  - 숨길 사업 표(`name="hide"`, `#hide-all`) 그대로 + `.table` 모양, 체크 행 `aria-selected`.
  - 아래 `.savebar`: 취소(조용한) · 확인 저장(주).

- [ ] JavaScript를 꺼도 모든 폼 제출이 된다
- [ ] 창 폭 1024px에서 가로로 넘치지 않는다(표 상자만 가로 스크롤)

## 6. 마크업을 검사하는 테스트 (깨지기 쉬운 곳)

- `tests/test_web.py` 726행 근처: `<th aria-sort="ascending"><a href="…">사업명</a>` — 정렬 머리글 `<th>`에 다른 속성을 붙이지 말고, ▲▼ 표시는 `<a>` 뒤 `<span>`으로 둔다. `aria-sort=`는 화면에 하나만.
- 857행 근처: 단가 `<option value="BIPV" data-source="태양광" data-price="…" selected>BIPV</option>` — 신재생 계획 편집의 option 속성 순서를 바꾸지 않는다.
- 1874행 근처: `class="setting-search"` 유지.
- 2136행 근처: 신재생에너지센터 링크 `<a href="https://nr.energy.or.kr/C0/CST_C0/login.do"…>` 유지.
- 그 밖에 화면 문구를 `in text`로 확인하는 테스트가 많다 — 문구를 바꾸지 않으면 대부분 그대로 통과한다.
